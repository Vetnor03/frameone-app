# Alfred hardware map and firmware compatibility review

Source of truth: the supplied one-sheet `Schematic.pdf` screenshots in the task request, plus explicitly reported bring-up observations. This document intentionally does not change firmware.

## Interpretation rules

- `Confirmed` means visible in the supplied schematic screenshots or explicitly reported as physically tested.
- `Unresolved` means the schematic image did not show enough detail, or the item requires datasheet confirmation not present in the schematic.
- Active levels are only called out when named nets (`*_N`) or schematic notes make them clear. Otherwise they are marked `UNRESOLVED`.
- E-paper functionality has not been physically tested because the panel has not yet been connected.

## USB subsystem

- J1 is `USB-C_Receptacle_USB2.0`, physical part/footprint noted as `HRO TYPE-C-31-M-12`.
- VBUS pins A4/B4 connect to `USB_5V`.
- D- pins A7/B7 connect to `USB_DM`; D+ pins A6/B6 connect to `USB_DP`.
- CC1 and CC2 have 5.1k pulldowns to GND through R3 and R2, respectively.
- SBU1/SBU2 are not connected.
- Shield and connector ground are tied to GND.
- U2 `TPD2EUSB30` protects USB_DP and USB_DM to GND before the ESP32-S3 native USB pins.
- `USB_5V` feeds BQ24074 input and is the visible USB-power rail. No separate ESP32 GPIO USB-presence divider is shown; Alfred-readable charger/USB presence should use `BQ_PGOOD_N` on GPIO17 if datasheet-confirmed.
- Risk: native USB CDC/JTAG can disconnect during reset and is not a persistent deep-sleep console.

## Main 3.3 V regulator

- U4 is `TPS63070RNMR` / `TPS63070` buck-boost regulator.
- Input: `SYS` to VIN pins 12/13; C7/C8 10 uF input capacitors.
- Output: VOUT pins 7/8 to `+3V3`; output capacitors C9/C24/C25 22 uF.
- Inductor: L1 1.5 uH between L1/L2 pins.
- EN pin 14 is tied to `SYS`, so +3V3 is expected always on whenever SYS is present; no ESP32 GPIO-controlled enable is visible.
- VSEL and VAUX are tied to SYS in the visible schematic; PS/SYNC appears tied to GND; PG pin is no-connect; FB/FB2 use resistor divider R11 316k to +3V3 and R12 100k to GND.
- Expected output is 3.3 V, physically measured as ~3.33-3.36 V.
- Exact feedback math and power-good behavior require TPS63070 datasheet if needed; PG is not firmware-readable.

## MAX17048 fuel gauge

- U5 is `MAX17048`.
- CELL pin 2 connects to `BAT`.
- VDD pin 3 connects to `+3V3`; GND pin 4 connects to GND.
- SCL pin 7 connects to `I2C_SCL` / GPIO8; SDA pin 8 connects to `I2C_SDA` / GPIO9.
- R14 and R15 are 4.7k pullups from SCL/SDA to +3V3.
- ALRT pin 5 appears unconnected; CTG pin 1 no-connect; QSTR pin 6 tied to GND.
- Expected I2C address is UNRESOLVED from schematic alone because the schematic does not encode the address. Stage 1 should scan the bus and then the implementation can cite the MAX17048 datasheet for the canonical address.

## E-paper power and driver circuitry

- `EPD_VCC` is a switched display-only 3.3 V rail generated from +3V3 by U8 `TPS22929D` load switch.
- U8 `ON` is controlled by `EPD_PWR` / GPIO12 and held off during boot/reset by R17 100k pulldown.
- J4 pins 15 and 16 connect to `EPD_VCC`; C14 1 uF is local to EPD_VCC.
- `EPD_VDD` has local C17 1 uF to GND and connects to J4 pin 18.
- E-paper reference/high-voltage section uses L2 10 uH, Q1 BSS138, D1-D3 MBR0530, C16-C23, R18 10k and R19 0.47R. Schematic note says this section generates/displays reference rails: `EPD_SW`, `CP`, `GDR`, `RESE`, `VSH2`, `VSH`, `VGH`, `VSL`, `VGL`, `VCOM`, `VDD`.
- J4 rail pins include `EPD_VSH2` pin 5, `EPD_VSH` pin 20, `EPD_VGH` pin 21, `EPD_VSL` pin 22, `EPD_VGL` pin 23 and `EPD_VCOM` pin 24, with local capacitors C18-C23 to GND.
- `EPD_BS` is tied to GND through R16 0R. Schematic note says GND = 4-line SPI, VCC = 3-line SPI, and RE:MIND V2 uses 4-line SPI.
- Expected safe Stage 2 power-up sequence: set EPD_PWR low; configure CS inactive, RST inactive, SCK/MOSI/DC stable; enable EPD_PWR; allow EPD_VCC to settle; initialize display driver with timeouts; perform one full refresh; put panel to sleep; drive EPD_PWR low.
- Expected safe power-down sequence is UNRESOLVED beyond the generic sequence above because the exact Waveshare Rev2.3 HAT/panel power-down timing is not shown in the schematic.
- Risk: any high-voltage display rails could remain charged temporarily on C18-C23/C16 after power-off. Do not touch the FPC or assume rails discharge instantly.
- Risk: boot-time unintended refresh is mitigated by R17 keeping `EPD_PWR` low, but Stage 3 must ensure GPIO12 is not driven high by early firmware or strapping effects.

## Future staged implementation plan

### Proposed compile-time target structure

Create a central board-target layer, for example:

- `frame/src/hardware/BoardConfig.h`
- `frame/src/hardware/BoardConfig.cpp`
- optional implementation files such as `BatteryBackendLegacy.cpp`, `BatteryBackendAlfred.cpp`, `DisplayPowerAlfred.cpp`

Proposed selection model:

```cpp
// Exactly one of these must be selected by build flags.
#define ALFRED_BRINGUP_STAGE_1
// #define ALFRED_BRINGUP_STAGE_2
// #define ALFRED_PRODUCTION
// #define LEGACY_PROTOTYPE
```

Recommended development default for Alfred work: `ALFRED_BRINGUP_STAGE_1`, because it keeps display power off, avoids deep sleep, avoids Wi-Fi/cloud, and avoids persistent production state changes. Recommended repository default until Alfred is approved: keep `LEGACY_PROTOTYPE` production environment unchanged and add a separate Alfred environment.

### Stage 1: Alfred diagnostics

Proposed implementation location: add a new diagnostic entry path in `frame/src/frame_v2.5.1.ino` guarded by `ALFRED_BRINGUP_STAGE_1`, with helpers in `frame/src/hardware/AlfredDiagnostics.*` if it grows beyond a small function.

Must do:

1. Boot reliably and call `Serial.begin(115200)` with native USB CDC enabled by build flags.
2. Print chip model, chip revision, reset reason, flash size, PSRAM detection and PSRAM size.
3. Configure `EPD_PWR` GPIO12 as output low immediately and never enable it.
4. Initialize I2C on SDA GPIO9 / SCL GPIO8.
5. Scan I2C and report discovered addresses.
6. Detect MAX17048 only by scan result plus later datasheet-backed address handling.
7. Read battery voltage/percentage only after adding a MAX17048 driver or confirmed library behavior.
8. Read `BQ_PGOOD_N` GPIO17 and `BQ_CHG_N` GPIO18 as raw levels and print them; label active meaning only after datasheet confirmation.
9. Avoid display init, deep sleep, Wi-Fi, backend calls, pairing/onboarding, OTA, and Preferences writes.

### Stage 2: controlled display test

Must require explicit compile-time selection `ALFRED_BRINGUP_STAGE_2` and must not run by accident. It should:

1. Print every step to Serial.
2. Hold `EPD_PWR` low while configuring GPIOs.
3. Configure CS inactive, RST inactive, DC/SCK/MOSI stable.
4. Enable U8 via GPIO12 only after safe preconditions.
5. Initialize the confirmed Waveshare 7.5-inch 800x480 monochrome panel driver.
6. Draw only a basic Alfred test image.
7. Perform one controlled full refresh.
8. Use BUSY timeouts so a panel fault cannot hang forever.
9. Put the panel into sleep.
10. Drive GPIO12 low to shut off `EPD_VCC` and wait for discharge/settling.
11. Avoid Wi-Fi, backend calls, pairing/onboarding and production behavior.

### Stage 3: Alfred production integration

1. Preserve existing RE:MIND behavior for `LEGACY_PROTOTYPE`.
2. Add `ALFRED_PRODUCTION` as a separate PlatformIO environment/build target.
3. Use central `BoardConfig` for MCU family, flash/partition expectations, USB mode, I2C pins, battery backend, charger GPIOs, display pins, display power GPIO and deep-sleep wake capabilities.
4. Support MAX17048 battery voltage/percentage and BQ24074 charger/USB status.
5. Support display power switching and safe panel shutdown before deep sleep.
6. Support ESP32-S3 deep sleep and wake sources without relying on legacy GPIO39.
7. Support OTA with the selected 16 MB partition scheme and a manifest path that cannot install an ESP32 binary on ESP32-S3 or vice versa.
8. Preserve pairing, rendering, cloud communication, app behavior, subscriptions, reminders, weather, events and backend schemas.

## Unresolved schematic/details list

- Exact BQ24074 `PGOOD` and `CHG` truth tables, including fault/charge-complete states, require datasheet confirmation.
- Exact BQ24074 charge current, input current, termination current, TS and timer behavior from R5/R6/R7/R4 require datasheet confirmation and possibly a closer crop around U7/R7 if R7 routing remains ambiguous.
- MAX17048 I2C address is not encoded in the schematic; Stage 1 should scan, and firmware docs should cite the datasheet before hard-coding.
- MAX17048 QSTR tied to GND behavior requires datasheet confirmation.
- E-paper BUSY polarity is not stated in the schematic.
- E-paper RST and CS active levels are not explicitly stated in the schematic, even though names/conventions suggest active-low.
- Exact Waveshare panel revision/driver class must be confirmed before Stage 2; schematic says custom footprint matches Waveshare Rev2.3 FPC orientation and existing 7.5-inch 800x480 monochrome panel is intended.
- Exact e-paper power-up/power-down timing and rail discharge times are not derivable from the schematic alone.
- ESP32-S3 strapping-pin and boot-time behavior for GPIO0, GPIO3, GPIO45, GPIO46 and any other relevant pins should be checked against ESP32-S3 documentation before assigning future functions or wake roles.
- ESP32-S3 deep-sleep wake eligibility for GPIO17/GPIO18/GPIO8/GPIO9/GPIO12 must be checked before Stage 3.
