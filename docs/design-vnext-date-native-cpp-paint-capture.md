# R4 Date: native C++ painter host 1-bit capture (DRAFT, NO FLASH)

**Purpose.** Previous #1458–#1462 HTML galleries are original-GFX SVG software studies, but the actual `ModuleDate.cpp` can reject candidates or paint different bitmaps. This independent diagnostic compiles **the unmodified production C++ `ModuleDate.cpp` itself** with original full `RemindEditorialFonts.cpp`, the original FreeSansNO glyph arrays and the real F2 role/calendar preflight. It exercises the public `ModuleDate::render(cell)` entrypoint; after saving pixels it separately calls the *same native, static editorial painter* to identify **native-admitted vs legacy-fallback** output and asserts identical byte-for-byte pixels for admitted cases.

The only replacement is a **host-only** `DisplayCore::get()` test device, with Adafruit_GFX-like original glyph bearings and pixel methods storing a full 800×480 **1-bit** frame in memory. This host capture renders GFX bitmap glyphs and records drawLine/drawCircle/fillRect/fillCircle results. It fails on any admitted pixel outside its assigned cell or visible matte `(58,39,680,436)`, on out-of-panel writes, missing ink, or mismatch between the real entrypoint and direct native editorial rendering. Cases include full Oct 2026 light/dark, Dec→Jan year rollover, 3×4 Date next to other modules and a holiday replacing botanical art. Native-admission failures are shown **as labelled legacy fallback only**, not misrepresented using the missing stock legacy 24pt font.

**Hard limitation:** This is a host-raster capture of actual C++ firmware drawing calls—not `GxEPD2_BW`'s internal buffer, panel-specific paged updates, a wire-level SPI transaction, or a physical epaper photo. Bresenham glyph rendering tracks Adafruit GFX semantics; `fillCircle` uses mathematically bounded disc raster. The legacy FreeSansBold24 dependency is represented by a host-only stand-in, **only to compile unrelated fallback branches**; therefore no legacy pixel mock is an approval target.

**Scope:** Host-capture implementation lives under `frame/tests/native_capture/`, its gallery/tool and tests, plus an isolated CI job step. **This PR also changes native Date-only C++:** an optional, default-FALSE editorial calendar-week width is increased by exactly 1px in `ModuleDate.cpp` and `DateMonthGridPlan.h`, and the non-production SVG review uses matching width. Standard/legacy calls retain the old 26px column; Surf, other modules, app/backend/OTA, and pilot behavior remain untouched. The test executes the actual repository C++ as compiled, not a separately rewritten painter.

**Acceptance gates still open:** actual GxEPD2 hardware framebuffer/panel waveform behavior; mixed modules painted together on-device; Day/Dark physical inspection at 1–2m; original known-good v2.7.3 rollback BIN+SHA independently verified. ## Native-gate defect discovered and corrected in this PR

The first successful compilation ran the genuine C++ entrypoint and found **0/5 Date-editorial admissions**, even though earlier source-GFX gallery images were green. Stage-by-stage replay of *unaltered* native planner functions located the failure at `gridFontFits` on BOTH current and next calendar grids. For the actual original `FreeSans9ptNO` GFXglyph assets, several of the 53 ISO week strings occupy **19px of ink** (e.g. `22`, `25`, `52`). The existing week column allocated 26px, but reserves 2px left and 6px right, leaving only 18px. Preflight responsibly rejected all such calendar proposals.

The fix is **only for explicit editorial Date calls**: reserve 27px (19px of inner ink), pass the same optional editorial width into `DateMonthGridPlan::plan`, measure actual `grid.weekW-8` in `gridFontFits`, and use 27px in the original-F1 QA gallery. Every old legacy/role caller retains default 26px and its unchanged drawing; no data or rows are removed, and fail-closed behavior remains intact. New native capture tests explicitly require successful admission on both October and December→January rather than declaring an all-fallback report successful.


## R4 follow-up: pinned GFX primitives + mixed-slot native audit (separate draft)

The first native host renderer's `fillCircle` drew a **Euclidean filled disc**. This is *not* the pixel pattern used by `Adafruit_GFX::fillCircle` in the firmware's pinned `Adafruit GFX Library@1.12.6`. That library fills vertical spans using `fillCircleHelper`; for radius 2 the reference raster contains 21 pixels vs 13 in a strict squared-distance disc. The **host-only** `CaptureFrameDisplay.h` now reproduces the pinned upstream fill routine and is checked independently for radii 0, 1, 2, 3, 7, 11, 16 and 30. See [upstream Adafruit_GFX.cpp tag 1.12.6](https://github.com/adafruit/Adafruit-GFX-Library/blob/1.12.6/Adafruit_GFX.cpp) and [GxEPD2_BW v1.6.4](https://github.com/ZinggJM/GxEPD2/blob/1.6.4/src/GxEPD2_BW.h). No firmware, fonts, Date geometry or Surf code is changed.

The new `audit_date_native_mixed_parity.py` compiles the **real native ModuleDate.cpp** and renders **every Date slot in all 11** already-established mixed-grid gallery scenarios, including default layout, pyramid, square, repeated Date, holiday, dark, year turn, and custom 3×4 alongside placeholders. It compares the JS/SVG source **admission decision** to the actual C++ Date-editorial gate and writes per-cell native hashes, safety counters and precise preflight failure stages as JSON in CI. Source-vs-native differences are listed as *open QA findings*, never quietly equated or turned into a false green pixel-diff. Only native-admitted pixels are checked as editorial output, and only Date is actually painted; **neighbor-module placeholders are not captures of Weather, Surf, Reminders, or News**. Both light and dark are covered in the existing scenario set.

The pinned GFX reference improves confidence in **drawing primitives**, not GxEPD2 page buffer identity. The host still uses a test-only display shim, a mock legacy 24pt font for fallbacks, and cannot prove SPI, panel rotation, grayscale, e-paper contrast, or real 1–2m legibility. The Layout Lab reference `RE-MIND-layout-review-100 (2).pdf`, page 1, seed `347015390`, has a very spacious single-month calendar and restrained botanical vignette, whereas the current opt-in large Date proposal includes two months and week numbers. A close editorial *visual resemblance* is an explicit human review goal, **not** something this host admission audit proves. Any perceptible difference must be reviewed before physical approval.
