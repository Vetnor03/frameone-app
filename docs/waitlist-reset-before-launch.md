# Waitlist reset before public launch

Waitlist numbers are generated by the PostgreSQL sequence `public.waitlist_number_seq`.
The sequence is owned by `public.waitlist_signups.waitlist_number`, and the column default calls `nextval('public.waitlist_number_seq')`.
The `waitlist_signups_waitlist_number_key` unique index prevents duplicate waitlist numbers.

## One-time reset

Run `supabase/migrations/20260609123000_clean_waitlist_test_signups_before_launch.sql` once immediately before launch, after confirming that `public.waitlist_signups` contains only test signups.

In Supabase:

1. Open the Supabase project dashboard.
2. Go to **SQL Editor**.
3. Paste the full contents of `supabase/migrations/20260609123000_clean_waitlist_test_signups_before_launch.sql`.
4. Run it once.
5. Confirm the SQL notice says the test waitlist signups were deleted and `public.waitlist_number_seq` was reset.

The script only deletes from `public.waitlist_signups`, resets the owned waitlist-number sequence, inserts one direct verification row, confirms it receives `waitlist_number = 1`, deletes that verification row, and resets the sequence again.
It does not call the application signup route, so it does not send a welcome email.

After the script succeeds, the table is empty and the next public signup will receive `waitlist_number = 1`; the following signup will receive `waitlist_number = 2`.
